# DigitalTwin-Agri — Machine Learning (DIGITALTWIN_ML)

The machine-learning and research core of **DigitalTwin-Agri**, the hybrid
digital-twin framework for groundnut (peanut) yield modelling described in the
IEEE paper *"DigitalTwin-Agri: A Hybrid Digital Twin Framework for
Next-Generation Smart Agriculture"* by Prabhash Nandan.

The idea explored here is a **hybrid** predictor: a deterministic,
physics-based crop model produces a baseline yield estimate, and a machine
learning model learns the *residual* — the part of the yield the physics
model misses — so the final prediction is `physics baseline + ML residual
correction`. This repository contains the notebooks that build, validate and
test that idea, together with the datasets they work on.

## Data

All files live in [`digitaltwin_ml/`](digitaltwin_ml/):

| File | What it is |
|---|---|
| `groundnut_yield_weather_merged_2000_2024.csv` | The real-world series: one row per year, 2000–2024 (25 rows), with columns `Year`, `area_ha`, `yield_kg_per_ha`, `production_t`, `temp_c`, `humidity_pct`, `rainfall_mm`, `solar_wm2`. |
| `synthetic_groundnut_digital_twin_dataset.csv` | 10,000 synthetic seasons generated by the physics-based season simulator in `4dataset_generation.ipynb` (120-day seasons, yields bounded to 500–3,000 kg/ha). Columns: `yield_kg_per_ha`, `seasonal_stress`, `LAI_max`, `leaf_growth_rate`, `RUE`, `harvest_index`. |
| `model_accuracy_comparison_table.csv` | The comparison output of the study: it tabulates MAE, RMSE and R² for three approaches — physical model only, machine learning only, and the proposed hybrid digital twin. See the file itself for the values. |

## Notebook guide

Run the notebooks from inside `digitaltwin_ml/` — they load the CSVs by
relative filename. Filenames are the original research filenames; the
numbering is as it was produced during the work (there is no `02`).

| Notebook | What it does |
|---|---|
| `01_eda_groundnut_yield.ipynb` | Exploratory analysis of the 2000–2024 yield/weather series (distributions, trends, yield-vs-weather relationships), then first forecasting models — Linear Regression, Random Forest (including a depth-limited variant) and SVR — using a time-based split (train on years ≤ 2018, test on later years). |
| `3validation_clean.ipynb` | Validation of the synthetic-season simulator against the real yields: checks that real yearly yields fall inside the synthetic distribution's P10–P90 envelope. |
| `4dataset_generation.ipynb` | Generates the 10,000-row synthetic digital-twin dataset with the season simulator (`simulate_season()`, seed 42) and writes `synthetic_groundnut_digital_twin_dataset.csv`. |
| `5ml_baseline.ipynb` | ML baselines on the synthetic dataset: Linear Regression and Random Forest regressors, with coefficient / feature-importance inspection. |
| `6digital_twin_feedback.ipynb` | The hybrid step: a deterministic digital-twin baseline function, a Random Forest trained on its residuals, and the combined corrected prediction. Saves the residual model to `dt_residual_model.pkl` with joblib. |
| `sanity_check.ipynb` | Reloads the saved residual model, checks the corrected predictions on a held-out split, and tries one hand-built input row. |
| `testing.ipynb` | A single-input end-to-end inference demo: baseline formula + saved residual model → final yield estimate. |

> **Note:** `dt_residual_model.pkl` is not committed to this repository.
> Run `6digital_twin_feedback.ipynb` first — it creates the file that
> `sanity_check.ipynb` and `testing.ipynb` load.

## Getting started

```bash
pip install -r requirements.txt
cd digitaltwin_ml
jupyter notebook   # or open the notebooks in VS Code / Colab
```

A sensible order is `01` → `3` → `4` → `5` → `6`, then `sanity_check` and
`testing`.

## The DigitalTwin-Agri family

This project lives across four repositories, each holding one snapshot of
the work:

- **[DIGITALTWIN_ML](https://github.com/PrabhashNandan78/DIGITALTWIN_ML)**
  (this repo) — the ML notebooks and datasets behind the paper.
- **[TWIN](https://github.com/PrabhashNandan78/TWIN)** — the farm
  simulation engine: plant-level farm, sensor and decision-support twins.
- **[DT_ENGINE_SKELETON](https://github.com/PrabhashNandan78/DT_ENGINE_SKELETON)**
  — the earlier, single-crop engine prototype that TWIN superseded.
- **[smartfarming](https://github.com/PrabhashNandan78/smartfarming)** — the
  original combined upload of all of the above.
